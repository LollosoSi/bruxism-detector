Manual procedures for desktop users, custom firmware compilation, and manual SVM training.

1. Desktop Software Prerequisites

  • Arduino IDE: Requires the "CMSIS-DSP" and "ArduinoBLE" libraries.
  • Processing: Requires the "Sound" library.
  • Python: Requires numpy, pandas, sklearn, and openpyxl libraries (install via pip).

2. Desktop SVM Training (Python)

If you are not using the Android app, you must train the model using Python:

  • Load main.ino into your Arduino and edit WifiSettings.h with your credentials.
  • Long-press the button on your Arduino until you hear confirmation beeps to stream FFT data.
  • Run fft_recorder_for_training. Use keys in the console: n (record non-clenching), c (record clenching), and s to save.
  • Move clenching.csv and non-clenching.csv to the folder containing data_classification_training.py and run the python script.
  • Paste the generated weights and bias into Settings.h. Note: Set bool use_eeprom_for_svm = false; in settings if you are not using the app.

3. Manual Calibration

  • Assisted Calibration: Long-press the button for 10 seconds. Follow the console instructions to record states, then replace classification_threshold in Settings.h with the suggested threshold.
  • Manual Calibration: Open the console at 500000 baud rate to see FFT evaluation scores. Find a custom threshold that sits between your lowest clenching score and highest non-clenching score.

4. Desktop Logger & Graph Utility

  • Run the main_logger Processing sketch on your computer to log events via UDP. Data is saved in the data/RECORDINGS/ folder.
  • To generate graphs, run the Java utility from the command line: java -jar generator.jar light.

5. Customizing Settings & Melodies

  • Edit variables under Settings.h to change detection timings (e.g., attesaPrimoBeep, numeroMaxBeep, periodoGrazia). Not really recommended as your graphs computations will be skewed
  • To change the alarm melody, edit the tune structs and the tune* tunes[] array using the definitions available in Notes.h.
